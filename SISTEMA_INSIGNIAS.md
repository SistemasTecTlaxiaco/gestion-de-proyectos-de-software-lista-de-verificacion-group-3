# Sistema de Insignias de Calidad

## 1. Propósito

El sistema de insignias permite representar de manera progresiva el nivel de cumplimiento de los criterios de calidad establecidos para el proyecto Hub Mixteca.

Las insignias se obtienen mediante evidencia verificable en GitHub y no únicamente por la existencia de documentación.

La progresión propuesta es:

**🥉 Bronce → 🥈 Plata → 🥇 Oro**

Cada nivel incorpora requisitos adicionales relacionados con el control de cambios, la verificación, la validación y la mejora continua.

---

## 2. Principios del sistema

El sistema se basa en los siguientes principios:

- Evidencia verificable.
- Trazabilidad de cambios.
- Control de requisitos.
- Verificación de funcionalidades.
- Validación de necesidades.
- Registro de hallazgos.
- Acciones correctivas.
- Mejora continua.
- Honestidad en la asignación de la insignia.

La insignia obtenida siempre deberá corresponder al resultado real de la auditoría.

---

# 3. 🥉 Insignia Bronce — Control de Cambios

## Descripción

La insignia Bronce representa el nivel inicial de calidad. Demuestra que el proyecto cuenta con mecanismos básicos para controlar y rastrear cambios relacionados con sus requisitos y documentación.

## Requisitos

Para obtener Bronce se requiere:

- Cumplir al menos 8 de los 12 criterios de auditoría.
- Contar con criterios de aceptación en las historias revisadas.
- Registrar los cambios relevantes mediante GitHub.
- Mantener evidencia del historial de modificaciones.
- Registrar los principales hallazgos encontrados durante la auditoría.

## Evidencias

Las evidencias pueden incluir:

- Issues.
- Commits.
- Historias de usuario.
- Criterios de aceptación.
- Historial de modificaciones.
- Documentación del proyecto.

## Significado

**Bronce = Control y trazabilidad.**

---

# 4. 🥈 Insignia Plata — Calidad Verificada

## Descripción

La insignia Plata representa un nivel superior en el que, además del control de cambios, existe evidencia de verificación y validación de las funcionalidades revisadas.

## Requisitos

Para obtener Plata se requiere:

- Cumplir al menos 10 de los 12 criterios de auditoría.
- Mantener trazabilidad de los cambios relevantes.
- Contar con evidencia de verificación.
- Contar con evidencia de validación.
- Registrar problemas o incumplimientos.
- Documentar las acciones correctivas.
- Identificar riesgos relevantes del proyecto.

## Evidencias

Las evidencias pueden incluir:

- Issues de requisitos.
- Issues de auditoría.
- Commits.
- Pruebas.
- Capturas de resultados.
- Evidencias de validación.
- Registro de riesgos.
- Acciones correctivas.

## Significado

**Plata = Control + Verificación + Validación.**

---

# 5. 🥇 Insignia Oro — Auditoría Integral

## Descripción

La insignia Oro representa el nivel en el que el repositorio demuestra el cumplimiento completo de los criterios de auditoría y evidencia un proceso de mejora continua.

## Requisitos

Para obtener Oro se requiere:

- Cumplir los 12 criterios de auditoría.
- Mantener trazabilidad de los cambios relevantes.
- Contar con evidencia de verificación.
- Contar con evidencia de validación.
- Registrar y corregir los hallazgos.
- Identificar los riesgos relevantes.
- Considerar las condiciones del contexto de Hub Mixteca.
- Documentar al menos una acción de mejora.
- Realizar una segunda revisión después de las correcciones.

## Evidencias

Las evidencias pueden incluir:

- Issues.
- Commits.
- Historial de cambios.
- Evidencias de pruebas.
- Evidencias de validación.
- Registro de hallazgos.
- Correcciones.
- Segunda auditoría.
- Documentación de mejora.

## Significado

**Oro = Control + Verificación + Validación + Mejora continua.**

# 7. Proceso para obtener una insignia

La obtención de una insignia seguirá el siguiente proceso:

**1. Auditoría**

Se revisan los 12 criterios definidos en `AUDITORIA_CALIDAD.md`.

↓

**2. Evidencia**

Se comprueba cada criterio mediante documentos, Issues, commits u otras evidencias disponibles en GitHub.

↓

**3. Resultado**

Se cuentan los criterios cumplidos.

↓

**4. Hallazgos**

Los criterios que no cumplan se registran como hallazgos.

↓

**5. Correcciones**

Los hallazgos pueden generar Issues de corrección y cambios en el repositorio.

↓

**6. Segunda revisión**

Se comprueba si las acciones correctivas fueron realizadas.

↓

**7. Insignia**

Se registra la insignia correspondiente al resultado real.

---

# 8. Reglas de trazabilidad

Para los cambios relevantes se utilizará la siguiente relación:

**Requisito → Issue → Cambio → Commit → Evidencia → Verificación → Validación**

Esto permite identificar el origen del cambio, su justificación y la evidencia relacionada.

---

# 9. Aplicación al contexto de Hub Mixteca

El sistema de insignias considera las características particulares del proyecto Hub Mixteca y su objetivo de atender la problemática de falta de canales de comercialización y visibilidad de mercado de Costuras de Tijaltepec.

Por ello, la auditoría considera aspectos como:

- Necesidades de los usuarios.
- Criterios de aceptación.
- Facilidad de uso.
- Acceso desde dispositivos.
- Condiciones de conectividad.
- Evidencia de validación.
- Trazabilidad de los cambios.

La calidad se evalúa considerando tanto el cumplimiento técnico como la correspondencia de las funcionalidades con los requisitos establecidos para el proyecto.

---

# 11. Honestidad académica

El sistema de insignias está diseñado para representar el resultado real de la auditoría.

No se asignará una insignia únicamente con el propósito de alcanzar un nivel determinado.

Si un criterio no cuenta con evidencia suficiente, deberá registrarse como parcial o no cumplido y, cuando corresponda, convertirse en una oportunidad de mejora.

---

# 12. Relación con la calidad del software

El sistema relaciona la progresión de las insignias con actividades de calidad:

| Insignia | Enfoque |
|---|---|
| 🥉 Bronce | Control de cambios y trazabilidad |
| 🥈 Plata | Verificación y validación |
| 🥇 Oro | Auditoría integral y mejora continua |

De esta manera, las insignias funcionan como un mecanismo de seguimiento del proceso de calidad y no únicamente como elementos visuales.
